Mapa

A static vector map export tool — author a map (projection, basemap, data layers, inset, scalebar, north arrow, raster/hillshade) and download it as a clean, layered SVG ready for print, Illustrator, Figma or Inkscape.

Built on Observable Framework for the page/build, and a zero-dependency Board panel manager (src/board/) for the draggable/dockable editor UI.

Getting started

Open Mapa: mbricknell.com/mapa — it runs in the browser, nothing to install.

The page is a board of panels — each one edits one part of the map. Panels you don't see are in the flyout on the right (drag them onto the board).

Make your first map

  1. Frame it. Pan and zoom the Atlas panel (the live map) to the area you want. That view is the map's extent — or shift-drag on it to draw an exact frame. Pick a projection and size in the Map panel.
  2. Add your data. In Data, search a country, province or sea by name (or drop a GeoJSON / TopoJSON file, or add points). Each layer gets its own fill, line, pattern and opacity.
  3. Style the base. Basemap toggles and colours land, ocean, borders, rivers and lakes; Raster adds hillshade or imagery; Inset, Scalebar and North arrow add the furniture.
  4. Annotate. Annotations adds callouts, arrows and text; drag them into place on the Output. Fonts sets the typefaces.
  5. Render (top right). The Output panel shows the export; Preview shows it full-screen. With live update off (the default) the map only redraws when you press Render — the Render button gets a ring when something has changed.
  6. Download the SVG (the ▾ menu has single layers and options). ⬇ JSON saves the project — drop that file on the Project / Template panel to pick up where you left off.

Start from a template instead: pick one in the Project / Template panel.

Saving your work

On mbricknell.com/mapa nothing is saved to the site — your project lives in the page until you download it:

  • ⬇ JSON (top right) downloads the project. To reopen it, drop the file on the Project / Template panel. Keep these files — they are your maps.
  • Download saves the SVG export.
  • The Projects list in the picker only shows maps that were put on the site itself, so it's the same for everyone and you can't add to it from the browser.

Running Mapa locally (see Fork & run your own copy) adds one thing: drop a downloaded JSON into src/mapa/projects/ and it appears in the Projects list — handy for a working set of maps.

Using your own data files

A web page can't open files on your computer by their path — browsers block that. So:

Where the data is Works
A file you drop in (or pick with … on the layer) for this session — Mapa reads it into memory
After a reload / reopening a saved project the project stores only a pointer (e.g. data/occupied.json), which the site can't follow to your disk — the layer shows missing. Click … on it (or drop the file again) to reconnect; its style and filter are kept
A URL (+ url, or any hosted GeoJSON / TopoJSON) always, for anyone who opens the project
Inside the site (projects/data/ on the server) always — but only whoever runs the site can put files there

To share a project that uses your own data, host the data at a URL — or send the data files along with the project JSON.

Fork & run your own copy

  1. Fork / clone the repository, then run it locally (you need Node 18+ and npm):

    npm install
npm run dev        # → http://localhost:3000/mapa

  2. Add the basemap data. The geometry isn't in the code — put these in src/mapa/files/ (GeoJSON or TopoJSON):

    File Layer Source
    countries.json land + borders Natural Earth admin-0
    ocean.json, lakes.json, rivers.json, coastlines.json water / coast Natural Earth physical
    innerlines.json internal boundaries Natural Earth / your own
    disputed_2026.json disputed areas your own
    inset-ocean.json, inset-innerlines.json the inset's coarse world Natural Earth 110m
    provinces.json, admin2.json (optional) admin areas for shape search geoBoundaries

    The layer → file mapping is src/mapa/js/basemap-layers.js (see Data below). A missing file just means that layer doesn't draw.

  3. Regenerate the indexes: npm run gen (projects, patterns, shape search, gazetteer). npm run dev keeps them current after that.

  4. Your own services:

    • Hillshade — the default layer points at https://tiles.mbricknell.com/hs.pmtiles. Host your own .pmtiles and change the URL in the Raster panel (or its seed in src/mapa.md).
    • MapTiler — tile layers use your own key in the URL (…?key=…).

  5. Deploy: npm run build, then serve dist/ from any static host. The host must support HTTP range requests — FlatGeobuf (.fgb) and PMTiles stream by byte range; run npm run build:basemap first so the .fgb files exist.

Projects you make are plain JSON: drop them in src/mapa/projects/ (or templates in src/mapa/templates/) and they appear in the Project panel.

Architecture

  • renderMap(settings) (src/mapa/js/mapa.js) is a plain function: build a settings object → get back an SVG DOM node (with .tilesReady / .projection attached). The engine is decomposed into one module per concern (basemap, raster, labels, inset, …); paint order is semantically meaningful (later = on top).
  • The editor (src/mapa.md) is a set of Board panels — Project, Map, Inset, Data, Scalebar, North arrow, Basemap, Raster, Project JSON, Atlas (nav pane), Output, and Style. Each is draggable/resizable/dockable; add/remove them from the 🧰 flyout.
  • State → render: field edits flow through one debounced entry point; buildProject(frameMap) turns the current panel/frame state into an Atlas project object, translate.js converts that to the settings renderMap consumes, and each output frame renders from its own saved state (no DOM-swapping).
  • Theming: the Style panel (board/theme.js) recolours the whole UI through 8 CSS tokens. Default theme is Parchment (the original warm light look); dark themes are available. App surfaces and the chrome bars derive from the theme tokens.

Panels

The editor is a Board of independent panels — drag by the ✥ handle to move, drag an edge to resize, drag to a window edge to dock, and use the ▤ button to cover/peek. Each panel's ? (in its title bar) opens its section here.

The 🧰 flyout (panel list). The tab on the right edge opens the panel list. Every panel that isn't on the board shows up there as a cartridge — a card with the panel's name, its one-line description, and its size (W×H). Drag a cartridge onto the board, or press its +, to place it; remove a panel with the ✕ on its title bar (it goes back to the list, keeping its state). Columns / Row px set the grid; reset board returns to the default layout. Your layout is saved in the browser.

Project panel

Project / Template. The starting point — load a saved project or a template from the dropdown, give it a name (used for the export filename), or drop/browse a .json project file. The panel edits the current project; data and view live in the other panels.

Map panel

Defines the export itself. Views (frames) — each frame is one export at its own extent + size; add frames to render several views of the same data in one go. Per frame: bbox (W,S,E,N) or "Atlas view as bbox", projection, width/height, buffer, background. Ratio buttons lock an aspect.

Inset panel

A locator mini-map. Toggle it on, set position / size / radius / projection, the land/ocean/border/inner-line colours, and the "you are here" marker (rect/dot/none) with its own style. Can follow the map view or lock to a fixed centre.

Data panel

Your own layers on top of the basemap. + points (CSV lines, or click the Atlas map), + shapes (GeoJSON/TopoJSON), + url (a live GeoJSON/TopoJSON endpoint). Each row toggles, restyles, sets opacity, and reorders (top of the list draws on top).

Scalebar panel

A two-tier distance scale — top/bottom values + units, anchor corner, and pixel offset.

North arrow panel

A north arrow — position, size, colour.

Basemap panel

Basemap layers. Toggle and style the base layers (land, ocean, borders, rivers, coastline, lakes, disputed). Per layer: colour, opacity, stroke width, simplify tolerance, and winding rewind. The layer set + defaults come from src/mapa/js/basemap-layers.js (see Data below).

Raster panel

Imagery layers. + tiles (a .pmtiles or XYZ URL, incl. hillshade/elevation), + worldfile (drop an image + its .wld/.pgw). Per row: opacity, blend mode, draw order. Blend modes (here and on Data layers): normal, multiply, screen, overlay, darken, lighten, hard-light, soft-light, difference, exclusion, hue, saturation, color, luminosity — the last four render in browsers but their Illustrator import hasn't been checked; color-dodge / color-burn are left out because Illustrator resets them.

Project JSON panel

The saveable project as formatted JSON — datasets appear as pointers, not geometry (the geometry stays in the repo/CDN). Use it to inspect or copy the project; it's also where an old pre-project-file Mapa config can be pasted for view-only render.

Atlas panel

The embedded interactive MapLibre navigation map (sandbox.html). Pan/zoom it to frame your export; shift-drag to draw a bbox; the ☰ menu toggles the pane's light/dark basemap, flat/globe, tilt (globe/tilt are needed for the satellite projection), 3D terrain + exaggeration, sky colours, and live lighting (sun, strength, shadow, highlight). It's a viewer/extent-picker — it doesn't change the export except by feeding it a bbox/camera. Its basemap is swappable via ATLAS_STYLE (see Data below) — any style.json or raster PMTiles.

Output panel

The rendered SVG export. Pan (drag) / zoom (scroll); Reset view refits, Crop to view sets the extent to the current zoom. A tab bar appears per frame. Download the full-stack SVG, a single layer, or every frame. Download ▾ → PNG + world file saves a raster for GIS: it takes the frame's current settings, swaps the projection to geoMercator, renders off-page (the preview and your chosen projection are untouched) and downloads <name>.png + <name>.pgw (EPSG:3857 metres, no .prj). image scale (1× / 2× / 4×) in the same menu sets PNG pixels per export pixel. If the export height is auto, the Mercator PNG's height can differ from the SVG's.

Style panel

Pick, edit, or save a theme — eight colour tokens recolour the whole UI. Default is Parchment (the original light look); dark themes are included.

Data & the basemap pipeline

Where layers are defined

One file: src/mapa/js/basemap-layers.js. Each entry is a layer:

{ key: "land", label: "land", file: "countries", defaultOn: true,
  fill: "#efeee8", fillOpacity: 1 /*, simplify: 0.01 */ }
Field Meaning
key layer id used across the editor + export.basemap[key]
label name shown in the Basemap panel
file data-file stem to load (the BASEMAP[<file>] bucket); layers may share one file (land + border → countries)
fileName actual filename stem if it differs from file (e.g. disputed → disputed_2026)
rewind false to skip the winding-flip heuristic (ocean)
defaultOn layer starts enabled on a blank project
stroke / strokeWidth / fill / fillOpacity default style
simplify default simplify tolerance in degrees (blank = full detail)

Both the render engine (loadBasemapData) and the Basemap panel read this list, so editing it is enough to add/restyle/retoggle a layer.

The Atlas (nav-pane) basemap

The layer list above is the SVG export's basemap. The interactive Atlas pane (sandbox.html, MapLibre) draws its own basemap from a style, set by one value in the same file:

export const ATLAS_STYLE = "light";
Value Loads
"light" / "dark" a built-in style (./styles/style-<name>.json)
"something.json" a style file in ./styles
"./…/style.json" or a URL any MapLibre style.json, local or remote (it can source its own vector/PMTiles tiles)
"./…/x.pmtiles" or a URL a raster PMTiles archive — auto-wrapped as a raster basemap

Change the value and reload to swap the Atlas basemap. Notes: a bare vector PMTiles carries no styling (it renders blank) — point a style.json at it instead; the Atlas pane's light/dark toggle is a runtime override on top of this default. Remote styles/tiles must be CORS-reachable.

Supported data formats

  • Vector (basemap + Data panel): GeoJSON, TopoJSON (auto-unwrapped), bare Feature[], FlatGeobuf (.fgb, basemap streaming), CSV (points), live URL.
  • Raster (Raster panel): PMTiles, XYZ tile URLs ({z}/{x}/{y}), worldfile images (.wld/.pgw).
  • Output: SVG (write-only).

Ingestion — order of operations

  1. Author — GeoJSON/TopoJSON → src/mapa/files/<name>.json
  2. Build — npm run build:basemap → src/mapa/files-fgb/<name>.fgb (prod streaming only)
  3. Config — basemap-layers.js maps each layer → its file + default style
  4. Load — loadBasemapData(): dev loads the whole .json; prod bbox-streams the .fgb → BASEMAP[<name>]
  5. Panel — config → Basemap rows; your toggles/colours/simplify → export.basemap[key]
  6. Render — drawBasemap() binds each layer to its geometry, applies style/simplify/rewind, paints in order → SVG

No build command? Dev still works (loads raw JSON directly). Only production needs the .fgb files; without them, those layers just don't draw.

build:basemap

npm run build:basemap              # convert every file in the config
node scripts/build-basemap.mjs rivers ocean      # only these stems
node scripts/build-basemap.mjs --simplify=0.01   # pre-simplify at build time

Reads the layer list from basemap-layers.js, so it converts exactly the files the app uses (dedupes shared files, honours fileName).

Performance notes

  • Regional / framed vector: FlatGeobuf wins big — it range-streams only the features in the frame's bbox; GeoJSON and TopoJSON always load the whole file. (At world scale there's no narrow extent to exploit, so .fgb is then just a compact binary, not a selective stream; TopoJSON is smaller on the wire than GeoJSON but needs a decode step.)
  • simplify (cuts point count) often helps more than the format choice, and shrinks the SVG.
  • Raster layers reproject per-pixel and embed as a base64 image inside the SVG (PNG for tiles, hillshade and worldfile rasters) — the heaviest path on both render time and output size. Prefer PMTiles over many XYZ requests; keep worldfile images modest.

Adding a basemap layer

  1. Add an entry to src/mapa/js/basemap-layers.js.
  2. Put the data at src/mapa/files/<file>.json.
  3. npm run build:basemap (for prod).
  4. New layers only: add a draw block in src/mapa/js/basemap.js (drawBasemap) — that's the one place paint order + geometry binding still live per-layer.

Atlas sandbox (sandbox.html)

The MapLibre map behind the Atlas pane also runs on its own: open sandbox.html directly and drive it with URL parameters. Flags (no value) are switched on just by being present.

URL parameters

Parameter What it does
debug Show the editing panel (Edit / Layer / View / Project tabs).
export Show the crop-box image-export tool (without debug, on its own; with debug, beside the editing panel — or open it there with the Export image button, which keeps your layer edits). Pick format (PNG, JPEG or WEBP; default PNG). Download also saves a world file — .pgw / .jgw / .wld to match, in EPSG:3857 metres — when the view is flat (no pitch, not globe; bearing is fine). The Sequence section steps one setting — bearing, pitch or sun — from → to by step and saves a frame per value into one .zip (see the cookbook).
embed Hide the floating Open in Mapa ↗ button.
style=… Basemap style (default dark): dark / light (built in), a file in src/styles/ (my-style.json), a path (./styles/my-style.json), a URL to any MapLibre style.json, or a raster .pmtiles. Works in every mode, ?export included. mode=dev loads the style-dev-* variants.
project=a.json,b.json Load one or more project files.
bbox=w,s,e,n Fit the view to a box.
center=lng,lat · zoom=N Start position.
pitch=deg · bearing=deg Start camera tilt and rotation.
maxzoom=N Max zoom (default 7). Overrides a project's view.maxzoom.
lock Freeze the view (no pan/zoom).
globe Globe projection instead of flat Mercator.
hide=group,layer-id Hide layers, by group (labels) or by id.
highlight=uid,uid Highlight features by uid.
terrain 3D terrain from the rgb height tiles (rgb.pmtiles, z0–8). Only visible with pitch > 0.
exaggeration=N Terrain height multiplier (default 1.5; 1 = true height).
lighting Live hillshade computed from the height tiles (replaces the pre-made hillshade while on).
sun=deg Light direction, clockwise from north (default 315 = north-west).
lightlock Lock the light to the camera: sun is measured from the top of the screen instead of north, so turning the map keeps the light on the same side of the image.
shade=0–1 Shading strength (default 0.5).
shadow=hex · hilite=hex Colours of slopes facing away from / towards the light, e.g. shadow=330066.
sky=hex · horizon=hex Sky gradient, top to horizon, e.g. sky=9cc3e6.
mapa Set by Mapa when the sandbox is its Atlas pane — not for direct use.

Colours in a URL go without the # (shadow=330066) — a bare # would cut the URL off there; %23330066 also works. The lighting highlight colour is hilite; highlight is only the feature uids.

Zooming past the data. Raising maxzoom lets you zoom past the height tiles' z8: MapLibre stretches the z8 tiles rather than asking for tiles that don't exist, so terrain and lighting keep working (softer). World-file images have no zoom limit and stay sharp.

View tab (?debug)

Live controls, applied as you drag:

  • Terrain: on/off and exaggeration (no upper limit). 3D only shows with pitch above 0.
  • Lighting: on/off, lightlock, sun (0–359°), shade (0–1), shadow and hilite colour pickers, each with its hex code beside it.
  • Camera: pitch (0–85°) and bearing (−180…180°). They follow the map if the camera is moved some other way.

Cookbook

Sandbox URLs are relative to the site root (e.g. http://localhost:3000/sandbox.html?… with npm run dev).

Zoom in further than 7

sandbox.html?maxzoom=12

3D terrain, tilted

sandbox.html?terrain&center=74.8,34.1&zoom=8&pitch=60&bearing=30

Terrain with live lighting from the east, purple shadows

sandbox.html?terrain&lighting&sun=90&shade=0.8&shadow=330066&hilite=ffee88&center=74.8,34.1&zoom=8&pitch=60

Close-up over low-res terrain with your own images on top: zoom past z8, load world-file images from the debug panel's Edit tab (drop the image + its .wld/.pgw).

sandbox.html?debug&maxzoom=14&terrain&lighting

Clean map to share (no labels, no button, view frozen)

sandbox.html?embed&lock&hide=labels&bbox=68,23,82,37

Georeferenced image from the sandbox (image + world file): frame it flat (pitch 0, not globe), drag the crop box, pick a format, Download. You get e.g. <name>.png + <name>.pgw; in QGIS set the layer CRS to EPSG:3857.

sandbox.html?export&lighting&center=74.8,34.1&zoom=6

Image sequence (turn the camera or move the sun): open the export view, set up the crop box, scale and format, then in the Sequence section pick bearing, pitch or sun, enter from, to and step, and press Export N frames. Each frame waits for the map to finish loading and is captured like a normal download. You get <name>-<setting>-sequence.zip with files like <name>-sun-045.png (negatives are neg030). Under the buttons is the frame count and an estimated time; during a run it shows the time left. The estimate learns from your runs (per setting and scale, saved in this browser). Press Stop to end early and still keep the frames so far. Play steps the live map through the same values (a short pause on each) without capturing or downloading anything — check framing and lighting first, then export.

sandbox.html?export&terrain&lighting&center=74.8,34.1&zoom=7
  • sun turns lighting on for the run. It only repaints the shading, so it's the fastest.
  • bearing with lightlock ticked (Sequence → Light; same as lightlock in the View tab, or ?lightlock) keeps the shading coming from the same side in every frame; without it the light stays fixed to north and swings round as the map turns.
  • bearing turns the map around the screen centre, not the crop box: keep the box centred or the area drifts. World files are included (with rotation) while pitch is 0.
  • pitch frames above 0 have no world file, and higher pitch loads more tiles, so it's slower.
  • Bearing, pitch and sun go back to where they were afterwards. The status line lists any value that hadn't finished loading after 30 s (that frame may be patchy).
  • Keep the tab visible while it runs — background tabs slow WebGL down.
  • For a full-quality video instead of the GIF: ffmpeg -framerate 12 -pattern_type glob -i '*-bearing-*.png' -pix_fmt yuv420p out.mp4

Export with your own style file: put the MapLibre style.json in src/styles/ (e.g. src/styles/my-style.json) and name it in the URL. Exports default to my-style-export.png.

sandbox.html?export&style=my-style.json&center=74.8,34.1&zoom=6
  • A style from elsewhere works too (style=https://…/style.json) if its host allows CORS.
  • Keep a background layer and, if you want Lighting to replace the pre-made shading, a hillshade layer — lighting is drawn just under hillshade and hides it while on. Without one, it's added on top of the style.
  • The style's glyphs and sprite URLs must be reachable, or labels and icons won't draw. The built-in styles use https://protomaps.github.io/basemaps-assets/fonts/{fontstack}/{range}.pbf.

Keyframe tween (fly between captured views): in the export panel's Keyframes section, frame the map and press + Capture view for each stop (it records centre, zoom, bearing, pitch, and sun when lighting is on). Set Between (frames added between each pair of views) and Easing (smooth settles on every view, linear keeps an even pace), press Play to watch it on the live map, then Export N frames for <name>-keyframes.zip (<name>-view-0001.png, …). Total frames = views + (views − 1) × between.

  • Each row has Go (jump there), ⟳ (replace with the current view), ↑ (move up) and ✕ (remove).
  • Save downloads <name>-views.json (the views plus Between and Easing); Load opens one and replaces the list. Load also takes a bare array of views, so you can write one by hand:
{
  "views": [
    { "center": [74.8, 34.1], "zoom": 6, "bearing": 350, "pitch": 0, "sun": 300 },
    { "center": [77.5, 32.5], "zoom": 7, "bearing": 10, "pitch": 45, "sun": 30 }
  ],
  "between": 24,
  "ease": "smooth"
}

center and zoom are required; bearing and pitch default to 0; sun is optional (turns lighting on).

  • The centre moves in a straight line on the Mercator map (the short way across the antimeridian); bearing and sun turn the short way round (350° → 10° passes through 0°).
  • World files are written for frames with pitch 0; the camera and lighting go back to where they were afterwards. follow camera (Sequence → Light) applies here too.
  • Views live in the page until you reload — Save them to keep them.

Low-res GIF of a run: tick GIF → with runs in the Image section and set its width (default 480 px) and speed (default 12 fps). Every Sequence or Keyframes export then also puts a looping <name>-…-sequence.gif / <name>-keyframes.gif in the zip, made from the same frames (256 colours per frame — fine for previews and sharing, not for print). Built as it goes, so it adds little memory.

Join clips into a video for Instagram (sequence player): open mapa/tools/sequence-player.html (e.g. http://localhost:3000/mapa/tools/sequence-player.html). Each load adds a clip: + Zip… (one clip per sandbox export zip — pick several at once), + Folder…, or + Images… — or drop them on the preview (each folder or zip becomes its own clip). Frames within a clip play in filename order (view-2 before view-10); clips play in list order.

  • Per clip: once or ping-pong, × times through, hold the last frame for some seconds, and position x / y % — where the clip sits when its shape differs from the output (which part a crop keeps, or where the bars go; 50/50 is centred). You can also drag the preview to move the current clip; double-click re-centres it. ↑ moves it earlier, ✕ removes it, clicking its name jumps there.
  • Timeline: speed (fps), Between clips a cut or a crossfade of N frames (last frame of one dissolving into the first of the next), and Repeat for the whole thing.
  • Playback covers the whole timeline: scrubber, ◀ ▶ (or ← → keys), space to play/pause; the label shows clip and frame.
  • Export the whole timeline as MP4 (H.264, what Instagram takes), GIF, or PNG frames (a zip of the finished frames — keeps transparency); Size original (first clip), ½, 1080×1080, 1080×1350 (Instagram post), 1080×1920 (Reel / Story) or 1920×1080; Fit keeps each frame whole with bars (pick their colour) or fills and crops — clips of different shapes are fitted the same way.
  • Look → Background (behind bars and any transparent pixels): transparent (checkerboard in the preview), a colour, or a gradient. Look → Vignette draws a gradient on top of everything (default: clear centre fading to 70% black at the edges, elliptical), in a blend mode (normal, multiply, screen, overlay, soft-light, color, luminosity, …).
  • Both gradients share one editor: Shape — linear (with an Angle, CSS-style: 0° to the top, 90° to the right), circle, ellipse (stretches with the frame) or box (contours follow the frame's edges); for the non-linear shapes, Centre (% across, % down) and Size. Stops are the break points: colour, position (%) and opacity each; + stop adds one halfway along the biggest gap, ✕ removes one (two minimum). The strip above the stops previews them.
  • MP4 can't be transparent, so anything still transparent exports as black; GIF transparency is on/off per pixel; PNG frames keep it all. The line above Export shows size, clips, frames and length, and warns when an MP4 is under the 3 s Reels minimum.
  • MP4 needs Chrome, Edge or Safari (they encode video in the page); in Firefox, export a GIF. Everything happens in the browser — nothing is uploaded.

Tweak lighting and camera by hand: open sandbox.html?debug&terrain&lighting, switch to the View tab and drag the sliders. Copy the values you like back into the URL (sun, shade, pitch, bearing).

Mercator PNG + world file for GIS (Mapa): render the frame, then Download ▾ → PNG + world file. Pick image scale first for a sharper PNG. Drop map.png + map.pgw into QGIS and set the layer CRS to EPSG:3857.

Notes

  • sandbox.html (the MapLibre "Atlas" nav pane) is embedded as an iframe and kept unchanged — it's out of scope for the editor refactor.
  • Production serves files-fgb/*.fgb, pmtiles/*, and the static tree from the CDN; a local checkout without files/ renders everything except the basemap geometry.
